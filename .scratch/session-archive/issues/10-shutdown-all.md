# 10 · 一键关闭所有运行中会话

Status: done
Blocked by: 05, 08

一个独立入口，拆掉当前所有活着的 agent，释放它们占用的资源。范围是**所有**活着的 agent，不限于已归档的。

这个能力本身独立于删除，但删除流程内部也会用到同一套拆除器（issue 05）。

## 要点

拆除是逐个进行的，其中任意一个失败不应中断其余——汇总报告成功数、失败数与失败原因。

拆除会话是有感的操作：正在运行的对话会被停掉。界面上必须先展示将要关闭的会话数并二次确认。

宿主没有任何 idle 回收或 LRU，resume 出来的 agent 活到进程退出；而且在 Web UI 里**打开一个会话就会把它 resume 成活 agent**。所以这个按钮的实际语义接近「释放后台占用」，README 里要这样说明，避免用户误以为它会关掉正在用的窗口。

## 验收

- 关闭后 `ctx.agents.list()` 为空
- 部分失败时其余照常关闭，并给出逐条原因
- 二次确认可取消

### 复审整改（2026-09-10）：术语缺口

复审指出「停机」「活体会话」是造出来的词，且 README 与 `text.ts` 说法不一致（README 写「全部停机 / 活体会话」，`text.ts` 写「关闭所有运行中会话」）。已统一到 `text.ts` 的说法：**运行中会话** + **关闭**，README 三处与能力表一并改过来，「停机」「活体」在包内已无残留。

**记录一处术语表缺口，不在本次自行补写 `CONTEXT.md`。**（已于 issue 14 补齐，见下。） 「一个会话正在运行」这件事，`CONTEXT.md` 里没有对应概念：那里的会话是「仅追加事件日志 + 不可变头部」，是磁盘上的东西；而这条能力操作的是它在内存里的 agent 实例——resume 出来、活到进程退出、占着写租约与资源。两者的生命周期完全不同，「关闭会话」关掉的是后者，日志一字不动。这与「删除」的区别正是用户最容易搞混的一处，值得由 `/domain-modeling` 正式定义（候选词：运行中会话 / 活跃 agent），而不是由一条 issue 顺手造词。在那之前，包内一律用「运行中会话」。

### 范围收窄（2026-09-14）

本条原文写的是「范围是**所有**活着的 agent」。这一点被 issue 13 与 14 改了，两处：

- **排除子代理**。子代理的 agent 属于父会话，父会话拆除时级联释放。单独列为目标只会和宿主的级联抢同一个 scope。
- **排除浏览器当前打开的会话**。这个按钮的用途是「释放后台占用」，前台正在用的那个不属于后台；它也是用户最不会预期被别的面板里的按钮关掉的那个。要关它走 issue 14 的标题栏按钮。

所以本条的验收「关闭后 `ctx.agents.list()` 为空」**不再成立**，现在的判据是：`roots()` 里除当前会话外全部关闭。

### 术语表缺口已补（2026-09-14）

上面记的那个缺口由 issue 14 补齐。`CONTEXT.md` 现在有三条：**Agent**（宿主既有概念：会话在内存中的运行实例）、**运行中会话**（持有 agent 的会话，内存判据，「运行中」不等于「正在输出」）、**关闭**（释放 agent，日志一字不改，与删除相对）。包内继续统一用「运行中会话」与「关闭」。
