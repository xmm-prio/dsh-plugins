# 领域文档

本文件规定工程技能在探索代码库时如何使用领域文档。

## 探索前按需读取

- 仓库根目录的 `CONTEXT.md`；或
- 若存在根目录 `CONTEXT-MAP.md`，读取它所指向且与当前主题相关的每个 `CONTEXT.md`；
- `docs/adr/` 中与当前工作区域相关的 ADR。

上述文件或目录不存在时，静默继续，不将缺失视为问题，也不主动建议创建。`/domain-modeling` 技能会在术语或决策实际明确后按需创建它们。

## 文件布局

本仓库使用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-<decision>.md
│       └── 0002-<decision>.md
└── src/
```

## 使用术语表中的词汇

当输出涉及领域概念（例如 Issue 标题、重构建议、假设或测试名称）时，使用 `CONTEXT.md` 中定义的术语，不使用术语表明确避免的同义词。

如果所需概念尚未在术语表中出现，应先重新确认项目是否已有对应语言；若确实存在缺口，记录它，留待 `/domain-modeling` 补充。

## 标记 ADR 冲突

若输出与已有 ADR 冲突，必须明确指出，而不能静默覆盖：

> 与 ADR-0007（示例决策）冲突——但值得重新讨论，原因是……
